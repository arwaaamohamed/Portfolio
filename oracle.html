Overview

Objectif : chiffrer les données au repos avec TDE, sécuriser le keystore, valider la solution par des tests, et définir une stratégie de sauvegarde/restauration compatible.

Contexte

  • Oracle Database 19c, importation d’une base existante via Data Pump
  • Choix de TDE (Oracle Advanced Security) pour le chiffrement au repos
  • Contrainte : schéma volumineux → chiffrement par tablespace privilégié

Mon rôle

Oracle DBA (POC) Security / Hardening Backup & Restore Technical documentation

Secure data starts with secure storage (and a safe keystore).

Approche

Une démarche en 4 étapes : import, chiffrement TDE, tests, puis plan de maintenance.

1) Importation & préparation

Data Pump
  • Restauration / importation de schémas via expdp/impdp
  • Gestion des contraintes d’espace disque (VM) et relance de l’import

2) Chiffrement TDE (AES-256)

Tablespace encryption
  • Création / gestion du wallet (keystore) et de la clé maître
  • Chiffrement par tablespace (plus adapté qu’un chiffrement par colonne sur un schéma volumineux)
  • Algorithme AES-256 pour assurer la confidentialité des données au repos

3) Tests de résilience

ORA-28365
  • Simulation d’un wallet fermé → accès impossible (ORA-28365)
  • Perte / restauration du wallet depuis une sauvegarde → données récupérées
  • Vérification des conditions d’accès selon les privilèges et l’état d’ouverture du keystore

4) Plan de maintenance

Backup / Restore
  • Sauvegarde logique via Data Pump
  • Sauvegarde indispensable du wallet / keystore (sinon les données deviennent indéchiffrables)
  • Documentation technique réutilisable pour l’équipe
